# Duewise 1.3.0

Prepared November 12, 2026. Minor release adding calendar export; reminder storage remains compatible.

## Calendar export

Open an active reminder and tap **Add to calendar**. Duewise opens a prefilled native calendar form for one event at the current due date and selected reminder time, with a default duration of 30 minutes and a copy of the notes. Review, edit, save or cancel in the calendar form. Recurring Duewise reminders export only their current due date.

Calendar events are independent copies. Later edits, completion, archive or deletion in Duewise do not update or remove calendar events. Repeated exports can create duplicates.

Android uses the supported `expo-calendar/legacy` system-intent entry point, without requesting calendar access. Android calendar read/write permissions are blocked in the manifest. Android cannot report whether the form was saved or canceled, so Duewise does not claim a successful save.

iOS uses Expo 57's calendar object API with write-only permission on iOS 17+. Older iOS versions use their calendar permission model. Permission denial shows recovery instructions. Duewise does not enumerate calendar contents or existing events. Reminders permission is disabled.

## Build

App config, package manifest/lock and Settings fallback use version 1.3.0. All EAS build profiles retain automatic build-number increments. This adds a native module and requires a new binary; no build has been submitted by this change.

For an installable Android APK: `npx eas-cli@latest build --platform android --profile preview`.

## Device checks

1. Verify Settings reports 1.3.0. Check a leap-day/month-boundary reminder opens at the chosen local date/time, including end times crossing midnight.
2. Review title and notes, change the selected calendar/time, and save. Verify one event appears and the Duewise reminder remains unchanged.
3. Cancel a second export. Verify Duewise does not claim that it was saved.
4. On iOS, deny permission and verify the recovery message; allow permission and retry.
5. On Android, test both an installed calendar app and a device without a handler. Verify errors remain recoverable and no calendar permission request appears.
6. Export a recurring reminder and verify it produces a single event. Confirm later Duewise edits do not imply calendar synchronization.
7. Check large text and dark mode, archived reminders, and older app binaries. The action is hidden on web and archived reminders; old binaries explain that a new build is required.

Automated checks and JavaScript exports do not prove native calendar-app rendering; test new Android and iOS binaries.
